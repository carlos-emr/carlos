# Detached records inside REST responses

AppointmentTo1 actually embedded Demographic and Provider, rather than an Appointment entity. Consultation search results embedded Demographic, Provider and ProfessionalSpecialist. MeasurementResponse held Measurement instances, and NoteTo1 held CaseManagementIssue instances. Appointment billing details also contained BillingONItem entities, discovered by walking the complete named response graphs.

These fields now contain dedicated detached snapshots with explicit member mappings. Serializers never traverse the managed source entities, persistence proxies or reverse clinical-note collections. Uninitialized required records/collections fail conversion explicitly; they are not replaced with empty successful results. Existing Java getter/setter descriptors remain as compatibility facades. Those getters construct identified detached domain views; changing a view does not mutate a managed record through a response object. Ordinary scalar properties and computed display members retain their wire names and values, apart from the SIN noted below. Mutable dates are copied.

The SIN is omitted from embedded patient records. The HIN is retained, as are the derived `label` and `standardIdentificationHtml` values that name it: existing appointment and consultation clients read the health card number from the embedded patient, and an embedded patient only appears inside a record the caller was authorized to read. The embedded patient is otherwise value-for-value what the entity serialized before the snapshots existed. Provider snapshots require billing-read permission for the same four billing identifiers protected by the other provider converters. Reverse note collections and extension-to-patient backreferences are not traversed. Note issues retain issue identity, codes, descriptions, flags, program and update data without transferring the reverse notes graph.

The billing snapshot retains the fee string, diagnosis, service identity, status and dates. The old entity's computed Optional fee getter caused both production JSON mappers to reject the entire response. Its detached wire counterpart is a nullable BigDecimal value under feeAsBigDecimal. The defunct sentinel retains its original fee string and has no numeric amount. Malformed stored amounts fail explicitly instead of becoming a successful null amount. Appointment history requires patient-specific appointment read and chart access before lookup. Billing details are omitted before any billing query unless global and patient-specific billing read are granted; these optional checks are readonly and do not lock the caller's session.

Published SOAP WSDLs remain unchanged. Native XML snapshots validate against the existing entity schemas under both Glassfish and MOXy, and unchanged entity readers consume them. Dedicated snapshots retain the original public-member XML binding, including the distinction between writable and readonly properties and alphabetical sequences while preserving the broader existing JSON property set. Owner sequences are pinned to the pre-snapshot source at 90f57841b59ab3838cc4fe00bd8356ad3bc674f4 in rest-embedded-release-baseline.json, including source hashes. Measurement maps and NoteTo1 issues remain JSON-only where the old bindings did not expose them in XML. This avoids inventing new XML elements merely to accommodate Java compatibility accessor names.

The native specialist reader already assigns its organization alias through setFirstName during a native entity round trip. The XML test explicitly characterizes that existing reader result and compares the snapshot through the same reader; it does not claim an identity-preserving legacy round trip. The new JSON snapshot retains the original firstName directly. Separate historical binary/XML inventory qualification remains tracked in the acceptance ledger.

EmbeddedRecordSnapshotsUnitTest compares populated values under both production JSON mappers (every patient member except `sin` equals the entity's), checks the HIN in patients embedded in appointment and both consultation search responses, verifies nested names and decoding, checks mutable-date ownership and initialization refusal, and rejects any JPA entity field reachable from the five named response graphs. EmbeddedRecordXmlContractUnitTest validates native output against unmodified generated entity schemas in all four writer/reader-provider combinations and pins all owner sequences under both providers. EmbeddedBillingItemUnitTest and real ScheduleServiceEndpointTest cases verify complete billing output, permission-dependent omission before lookup and chart denial. Existing manager, endpoint, JSON date, shared-JAXB-context and fourteen published-WSDL checks remain required.

Full-suite follow-up preserves extension values, numeric clinical timestamps and Java serialization of the detached graphs. The three domain types given compatibility constructors retain their pre-change serialVersionUID values. Synthetic binding inputs are derived from the original domain producers so their computed aliases agree; frozen XML fixtures and native entity schemas remain unchanged. The corrected 438-case XML, snapshot and endpoint selection passes with no failures, errors or skips.
