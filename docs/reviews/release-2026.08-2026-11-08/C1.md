## Findings

### C1-1: The CPP edit popup now shows hex escapes in issue labels (`Social\x20History\x20as\x20part\x20of\x20cp\x70`)
- Severity: Medium
- Category: regression
- Confidence: Confirmed
- Commit: 23154da2 (#5459) (OWASP Encoder 1.4.1 → 1.6.0). The double encoding it exposes is pre-existing.
- Location: `src/main/webapp/WEB-INF/jsp/casemgmt/viewNotes.jsp:177-186` (inner encode) and `:198`, `:207`
  (outer encode); `src/main/webapp/js/newCaseManagementView.js.jsp:1179-1188` (consumer);
  `pom.xml:354` (`owasp-encoder.version` 1.6.0; main `pom.xml:334` = 1.4.1)
- Problem: viewNotes.jsp builds `strNoteIssues` with
  `.append(SafeEncode.forJavaScript(iss.getIssue().getDescription()))`. It then encodes the whole
  string again with `<carlos:encode value='<%= strNoteIssues.toString() %>' context="javaScriptAttribute"/>`
  inside `onclick="showEdit(...)"`. The browser removes only the outer layer, so `showEdit` receives the
  inner JavaScript escapes as literal text. It then does `noteIssues.split(";")` and renders
  `escapeNoteText(issueArray[idx + 2])` as the label of each issue checkbox.
  - Under encoder 1.4.1, the inner `forJavaScript` escaped only `"&'-/\`. Most labels were unaffected.
  - Under 1.6.0 it also escapes spaces, `!$<>{` and backticks, and a trailing c/i/p/r/s/t, so almost
    every label is now corrupted.
  #5459 fixed the neighbouring `strNoteExts` metadata in the same `onclick`. Its upgrade note says
  "pre-encoding metadata as JavaScript would expose hex escapes in ordinary text", but the issue
  descriptions in the same payload were missed. The "Add Item" path (`viewNotes.jsp:103`, raw
  `cppIssue` from `CaseManagementView2Action.java:1208`) is encoded once and is correct.
- Evidence: the real pipeline (inner `Encode.forJavaScript`, then outer `forJavaScriptAttribute`, then a JS literal),
  using the seeded CPP issue text (`database/mysql/migration/...`: `'Social History as part of cpp'`):
  - 1.4.1 → `label shown: Social History as part of cpp`
  - 1.6.0 → `label shown: Social\x20History\x20as\x20part\x20of\x20cp\x70`
  - Also `Ongoing\x20Concerns\x20as\x20part\x20of\x20cp\x70` and `Diabetes\x20mellitu\x73`.
  The modern chart's CPP panels load this JSP (`newCaseManagementView.js.jsp:489-509` →
  `CaseManagementView?method=listNotes` → `struts-clinical.xml:181` `listNotes` → `viewNotes.jsp`).
- Impact: every edit of an existing Social/Medical History, Ongoing Concerns, Reminders, Family
  History, Risk Factors or Other Meds entry shows garbled issue checkbox labels, and so does any
  clinical issue attached to the note. Only `issue_id` is submitted, so no stored data is corrupted,
  but clinicians see it on a core charting screen. A clinician may also untick an unreadable issue,
  which moves the note out of its CPP section. No test covers these labels. The unit test uses
  synthetic `noteIssues` strings, and the #5459 Chromium checks covered only `strNoteExts` values.
- Correction: append the raw description at `viewNotes.jsp:183`, or `SafeEncode.forUriComponent`
  plus a client-side `decodeURIComponent` if `;` must be protected, matching the `strNoteExts` fix.
  Keep the single outer `javaScriptAttribute` encode. Add a regression test that renders viewNotes,
  opens Edit and asserts the label text. `CaseManagementView2Action.getNoteExt`
  (`CaseManagementView2Action.java:1652-1665`) still uses `Encode.forJavaScript`, but its
  `getCppAdditionalData` has no caller. Delete it or align it.

### C1-2: The #5747 API inventory predates later removals, and behaviour-contract changes appear in no upgrade note
- Severity: Low
- Category: docs
- Confidence: Confirmed
- Commit: b6fa8255 (#5694), 5f9ca145 (#5518), d740e534 (#5705), d9f0a955 (#5512), 23154da2 (#5459)
- Location: `docs/release-notes-2026.08.md` (no upgrade/API section);
  `src/main/java/io/github/carlos_emr/AppointmentMainBean.java`; `src/main/java/io/github/carlos_emr/carlos/util/SqlUtils.java`;
  `docs/security-object-diagnostics.md`; `docs/security/owasp-encoder-upgrade-2026-10.md`
- Problem: #5747 lists the 29 types changed up to 4b302882. These changes are absent from #5747 and
  from the release notes:
  - **Removed after 4b302882**
    - `AppointmentMainBean`: 15 public methods removed (b6fa8255). These are the `queryResults`,
      `queryResults_paged` and `queryResultsCaisi` overloads and `getString(ResultSet, String|int)`.
      Custom JSPs commonly reached these through `<jsp:useBean id="apptMainBean">` (8 in-tree JSPs
      still declare it). `doConfigure(String[][])` still accepts query arrays that nothing can
      execute now.
    - `util.SqlUtils`: `getQueryResultsList(String)`, `getQueryResultsList(String, Object...)`,
      `getRow(String)` and `getRow(String, Object...)` removed (b6fa8255).
    - `billings.ca.bc.pageUtil.BillCodesTableWrapper` deleted (5f9ca145).
    - The WAR no longer contains displaytag, JFreeChart, POI or Selenium (5f9ca145). This is stated
      only in `docs/dependency-footprint-5472.md:3`. A custom JSP with `<display:table>` or a
      JFreeChart import now fails at first request.
    - `form.FrmGrowth0_36Record` deleted (d740e534; already reported as S20-3).
  - **Behaviour contracts with unchanged signatures**
    - d9f0a955 changed `toString()`:
      - `AbstractModel.toString()` now returns `Type[id=N|protected]` for every JPA entity without
        its own override, and `BaseObject` returns `Type[protected]`.
      - About 60 explicit overrides are now type markers.
    - d9f0a955 changed `equals()` and `hashCode()`:
      - `Issue`, `ClientImage`, `CaseManagementCPP` and `FieldDefValue` changed from all-field
        equality to persistent-key equality, with reference identity for unsaved instances.
      - The unsaved-instance `super.hashCode()` of `CaseManagementNote` and `CaseManagementIssue` is
        now a per-type constant.
    - Audit `log.data` text changed to fixed text instead of an object dump:
      - `RxManager.getDrug` and prescription discontinuation (`RxDeleteRx2Action.java:404`);
      - `AppointmentManager.addAppointment` (`ScheduleManagerImpl.java:221`, through `AbstractModel`);
      - FHIR provider retrieval.
    - `Encode`/`SafeEncode.forJavaScript*` output bytes changed (23154da2): see C1-1 for the effect
      on misuse outside a JS string literal.
  These are documented only in the two docs pages named above, not where site administrators look.
- Evidence:
  - `git show b6fa8255 -- src/main/java/io/github/carlos_emr/AppointmentMainBean.java` → 15 `-    public ... queryResults*/getString(ResultSet` lines.
  - `git show 5f9ca145 --stat` → `.../pageUtil/BillCodesTableWrapper.java` deleted.
  - `docs/release-notes-2026.08.md` has 5 sections: birthday XML, HCV/MCEDT, REST appointment, Inbox, startup.
  - In-tree consumers were all migrated: grep finds no reference in `src/main/webapp` or `src/main/resources`.
- Impact: sites with custom JSPs, reports or plugins (the audience #5747 targets) hit compile
  failures or behaviour changes (equality, toString, JS encoding) on upgrade, with no migration note.
- Correction: extend #5747 and its upgrade note with the items above (cite S20-3 for
  `FrmGrowth0_36Record`), and link the two docs pages from the release notes.

## Checked and found OK
- `forJavaScript` misuse candidates are all JS contexts. Checked: addEditServiceCode, billingShortcutPg1, scheduletemplatecodesetting, guidelineDetail, showDocument, EditFlowsheet, attachDocument (`<c:set>` then `forHtmlAttribute`), billingON (`<c:set>` inside JS strings), the `.js.jsp` files, ChartNotesAjax (`insertReason`, template autocomplete), LeftNavBarDisplay/NavBar URLs, contact searches, `Demographic` copyToClip builders, `CreateLabLabel2Action`/`RptByExampleQueryBean`/`EctMeasurements2Action` encoded values (unused downstream).
- `JSON.parse('<carlos:encode … context="javaScript"/>')` in ViewScript2.jsp:1535 is decoded by the JS literal before parsing.
- The `toString()` audit in `docs/security-object-diagnostics.md` matches my own search. No parsed, compared, keyed or rendered use of a reflective representation remains.
- No removed API is referenced from any non-compiled fragment, struts/Spring XML, properties, service loader or DRL.
- `Issue`, `ClientImage`, `CaseManagementCPP` and `FieldDefValue` equality: all collection use is id- or index-based. `FieldDefValue.JpaId` has value equality.
- Bulk privilege helper: the absent-object vectors match `getPrivilegeProp`, the case-insensitive key map tolerates MariaDB pad/case matching, and per-object row order is preserved.
