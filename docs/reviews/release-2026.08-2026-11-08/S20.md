## Findings

### S20-1: The rewritten Growth 0–36 save has no stale-version check and no duplicate-submission guard (Growth analogue of #5759)
- Severity: Medium
- Category: omission
- Confidence: Confirmed (code path traced; the behaviour is carried over from main, not a regression)
- Commit: d740e534 (#5705)
- Location: `src/main/java/io/github/carlos_emr/carlos/form/Growth0To36FormService.java:91-102`, `src/main/java/io/github/carlos_emr/carlos/form/Growth0To36Form.java:31-36`, `src/main/webapp/WEB-INF/jsp/form/formGrowth0_36.jsp:317`
- Problem: #5705 replaced the Growth save with a new service boundary but kept "every POST appends a version built only from the posted fields". The posted `formId` is checked for patient ownership, never for being the newest version. No `FormSubmissionGuard` token exists. CLAUDE.md ("Duplicate Submissions and Stale Edits") requires an edit form that posts every field to refuse a stale rendering. #5759 was filed for the same gap in BC-AR 2020 (#5605), which also rewrote its save path.
- Evidence:
  ```java
  public int saveVersion(LoggedInInfo actor, int patient, int sourceId, Properties values) {
      require(actor, patient, "w");
      if (sourceId > 0) requireVersion(patient, sourceId);   // ownership only
      FormGrowth0To36 form = Growth0To36FormValues.fromProperties(values); // posted fields only
      ... forms.persist(form);
  ```
  Readers always take the newest row:
  - `FormGrowth0To36Dao.findHistory` sorts `ORDER BY f.id DESC`.
  - The Rourke graphs use `pforms[0]` (`FrmRourke2020Record.java:234`, `FrmRourke2017Record.java:244`, `FrmRourke2009Record.java:231`).
  - The `formId=latest` shortcut takes the latest `formEdited`.
- Impact: two clinicians edit the same child's chart, both starting from version N, and save. The second save becomes the "current" chart and silently drops the first clinician's measurement rows. The Growth chart, the Rourke growth-graph overlay and the latest shortcut no longer show them; they survive only in history. A double Save or a re-POST adds duplicate versions. The `confirm()` dialogs make a double click less likely but do not prevent it. Nobody is told.
- Correction: refuse the save with a form error or 409 when `sourceId` is not the patient's newest Growth ID, using the same pattern as `DemographicEditVersion`. Read the newest ID under a lock, or compare it with `findHistory(patient).getFirst().id()` inside the save transaction. Add a `FormSubmissionGuard` token to `formGrowth0_36.jsp` and claim it in `Frm2Action` for this form class. This could be folded into #5759 as a shared Frm2Action fix.

### S20-2: Growth XML-archive failures are logged with no cause, so operators cannot diagnose them
- Severity: Low
- Category: silent-failure
- Confidence: Confirmed
- Commit: d740e534 (#5705)
- Location: `src/main/java/io/github/carlos_emr/carlos/form/Growth0To36FormService.java:117-133`
- Problem: when `save_as_xml=true`, any failure after commit is caught and logged as a fixed sentence with no exception class or cause. This covers the read, the path, the directory and the transform. The legacy path, which other forms still use, logged the exception (`FrmRecordHelp.java:208-212`). The intent was to keep PHI out of the log; the side effect is that a misconfigured `form_record_path` produces only repeated identical ERROR lines.
- Evidence: `} catch (Exception _) { MiscUtils.getLogger().error("Unable to archive committed Growth form XML; continuing without XML copy"); }`. The legacy code is `MiscUtils.getLogger().error("Unable to archive form record XML after database save; continuing without XML copy", e);`.
- Impact: sites that rely on the XML interchange copy lose it with no actionable error. The form itself is committed, so clinical data is safe. The log wording also changed, so log-based monitoring that matched the old message stops matching.
- Correction: log the exception class name, which carries no PHI, and a coarse stage (read, path or write). For filesystem failures, also log the configured archive directory, but never the file name, which contains the demographic number.

### S20-3: Removed public type `FrmGrowth0_36Record` is not in the upgrade notes, and two inventories still list it
- Severity: Low
- Category: docs
- Confidence: Confirmed
- Commit: d740e534 (#5705)

It also added a public member to `FrmRecord`: `saveFormRecord(LoggedInInfo, Properties)`. #5747's removed-API list was compiled at 4b302882, before #5705, so it covers neither change. - Impact: a custom JSP or plugin that instantiated `FrmGrowth0_36Record` directly fails JSP compilation after upgrade, with no migration note. The stale inventory over-reports remaining work.
- Correction: add `FrmGrowth0_36Record` (replacement: `new FrmRecordFactory().factory("Growth0_36")` or `Growth0To36FormService`) and the new `FrmRecord` overload to the #5747 note. Mark the TSV row as migrated by #5705.

### S20-4: Growth integration tests do not prove that five header fields round-trip
- Severity: Low
- Category: test-gap
- Confidence: Confirmed
- Commit: d740e534 (#5705)
- Location: `src/test/java/io/github/carlos_emr/carlos/form/Growth0To36FormPersistenceIntegrationTest.java:69-118` and `:474-484`
- Problem: the suite sets `recordNo`, `motherStature`, `fatherStature`, `gestationalAge` and `edc`, but never asserts them against the submitted values. It does assert `patientName`, all 120 slot fields and `formCreated`. `assertLegacyProperties` compares the new reader with the legacy reader on the same stored row. That proves read parity, but a writer that stored NULL for one of these fields would pass both readers and the XML comparison.
- Evidence: the only header assertion in the round-trip test is `loaded.getProperty("patientName")` (`:111`). `motherStature` is checked only for the NULL case (`:224-229`).
- Impact: low today, because I verified the mapping by hand (`Growth0To36FormValues.java:21-57`, entity columns against the DDL). It matters because the brief and the doc claim a full round-trip ("compares all persisted properties"), and a future mapping edit could drop one of these fields unnoticed.
- Correction: in the round-trip test, assert `loaded.getProperty(k).equals(values.getProperty(k))` for every key in `values` that is a column, or at least the five fields above.

## Checked and found OK
- **BCAR transaction:**
  - `saveVersion` is `@Transactional(rollbackFor=Exception.class)` and is reached through the proxy (`SpringUtils.getBean`).
  - `batchPersistAtomically` is REQUIRED, so its 50-row flush+clear stays inside the transaction.
  - The header uses IDENTITY and is rolled back on failure.
  - `clear()` only detaches the already-flushed header and the unmodified source rows; only `getId()`/`getProviderNo()` are read afterwards.
  - Navigation is computed after commit.
- **BCAR copy/update logic matches the old code apart from the intended fixes:**
  - Unticked boxes and blank current-page fields are dropped.
  - Global fields (page 0) are always copied and blanked only when posted blank.
  - Checkbox `on`/`checked` maps to `X`.
  - No duplicate composite keys are possible, because DB `val` is NOT NULL, so `currentValues` never holds null for an existing row.
- **BCAR authorization:** unchanged (`_form` w, `_demographic` w, `requireFormOfPatient`) and now inside the transaction. `FormBCAR2020*Dao` are single XML beans and the service is a single scanned `@Service`.
- **BCAR tests:** they use real Spring/JPA commits and rollbacks (H2 plus MariaDB generated and BC-Flyway lanes), cover batch boundaries 0/1/49/50/51/101 and failure at each stage. A unit test covers the page-matched update.
- **Growth mapping:** column names, lengths, DATE/TIMESTAMP types and nullability match the baseline DDL. All 20 slots are mapped. An all-NULL slot returns an empty measurement without being written back, so a load causes no spurious UPDATE. The `columnDefinition="timestamp"` is needed only for generated schemas.
- **Growth registration:** main uses `packagesToScan` for `form.model`. `@Repository` is picked up by both scans, with the same bean name, which is harmless. The test EMFs scan `form.model`, and the service is proxied (the test asserts `isAopProxy`).
- **Growth read/write parity with the legacy JDBC path:**
  - same Properties keys and formats;
  - `Misc.getString` trimming reproduced;
  - untrimmed stored text;
  - slash/ISO date parsing identical to `updateResultSet`;
  - NULL versus "" preserved;
  - `formEdited` is now();
  - new-form prefill identical, including `first + " " + last`;
  - provider comes from the authenticated actor and the posted `provider_no`/`ID` are ignored.
- **Growth transactions:**
  - `load` is read-write by design, for the health-care-team audit.
  - The `readOnly` DAO reads join the outer transaction without effect.
  - The archive runs only `afterCommit` through REQUIRES_NEW, and no file is written on rollback.
  - History reads are patient-bound.
  - The grouped query is `ONLY_FULL_GROUP_BY`-safe and keeps the old ascending day order.
- **Growth message choice:** a missing ID and a foreign ID give the same "missing required sec object (_form)", which deliberately gives no existence oracle.
- **No leftovers:** no code, config or JSP references remain to `FrmGrowth0_36Record`. `FrmRecordFactory` dispatches `Growth0_36` after the allowlist check, and the factory unit test was updated.
- **Doc accuracy:** `docs/form-persistence-migration.md` claims match the code (131 columns, 61 remaining records, archive and audit behaviour, nineteen evidence cases).
- **Minor qualification nit:** the `java-all` (H2) lane's `requiredFamilies` lists BCAR (15) but not Growth (19). Growth is enforced in all three MariaDB lanes, so the risk is low.

## Declined to judge
- How MariaDB Connector/J 3.5.11 decodes `0000-00-00` DATE/TIMESTAMP values. Such values can come from old OSCAR data or from an XML re-import of empty date elements under `sql_mode=''`. The legacy reader and Hibernate both use `getDate`/`getTimestamp`, so the behaviour is equivalent, but I could not inspect the driver to confirm it returns null rather than throwing.
- The Hibernate 7 default for `hibernate.check_nullability` with the new `nullable=false` attributes. It has no observable effect, because no writer sets those attributes to null.
- The cost of the extra demographic and health-care-team audit row written on every Growth load, print or Rourke graph render. This is deliberate per the doc.
