# PR #5495 review: response-filter lifecycle (spec for the improvement plan)

Reviewed head: `a36383ddd293d1e8c572c4a10f30d473c76e843e` on `fix/5487-response-filter-lifecycle`,
base `release/2026.08`. Companion plan: `2026-11-04-pr-5495-improvements.md`.

## Verdict

A sound, well-tested fix within the existing four-wrapper architecture (sanitizer, CSRF capture,
logout decorator, privacy decorator). Not mergeable as it stands: the base moved underneath it, and
the three wrappers do not share one rule for `resetBuffer()`.

Verified assumptions: Tomcat 11's `Response.setHeader("Content-Length", null)` removes the length;
JavaMelody 2.9.0's `FilterServletResponseWrapper.reset()` drops its cached writer.

## Blocker: base moved

Commit `c56b019a49` (PR #5618, "honor full response resets across decorators") landed on
`release/2026.08` after the PR's last base merge and adds a subset of this PR's `reset()` work.

- `CsrfGuardScriptInjectionFilter`, `LogoutBroadcastFilter`, `ResponseSanitizationFilter` conflict.
  The PR side is a superset in each case, except the sanitizer, where the base calls
  `discardCapturedOutput()` and the PR sets `committed = false`; the union is correct.
- `PrivacyStatementAppendingFilter` auto-merges into a compile error: #5618 added `reset()` after
  `getWriter()`, the PR added `reset()` after `resetBuffer()`. The merged class has two
  `public void reset()` methods (merged tree lines 391 and 509). Keep the PR's.

## Design findings

1. **`resetBuffer()` rule differs per wrapper; the doc claims one rule.** `docs/response-filter-lifecycle.md`
   says a buffer reset keeps a pending length. CSRF and privacy wrappers keep it; the logout wrapper
   (`LogoutBroadcastFilter.java` `resetBuffer()`) clears its pending length, as before the PR.
   Behaviour change versus base: an authenticated request whose action sets a non-HTML type and a
   Content-Length with no channel open, then forwards to a JSP, now has that length re-published
   by the privacy wrapper when the JSP opens the writer, so the JSP body is framed by the pre-forward
   number. Before the PR the logout wrapper dropped it. Rule to adopt everywhere: any length, pending
   or published, that predates an accepted `resetBuffer()` described the discarded body and is dropped;
   a rejected reset leaves all state unchanged; `reset()` clears everything.
2. **Three copies of one defer/publish/retract state machine** with divergent edge rules (malformed
   Content-Length warned-and-ignored in two, passed through in the privacy wrapper; split int/long
   fields versus one `Long`). Follow-up, not in-PR: a shared value object.
3. **Pre-existing silent omission routed through new code.** The "notice already printed" guard is a
   session attribute; two concurrent requests in one session race and the loser ships a printable
   page without the confidentiality notice. The attribute is cleared in `finally`, so it has no
   legitimate cross-request effect; a request attribute (already the no-session fallback) is enough.
4. **Smaller items.**
   - `PrivacyStatementAppendingFilter.doFilter` decides HTML with `toLowerCase().startsWith("text/html")`
     while its wrapper uses `RequestNegotiation.isHtmlContentType`.
   - `noticeCharset()` duplicates the sanitizer's private `resolveEncoding()`.
   - Logout `reset()` sets `chainComplete = false`, unreachable after chain completion.
   - `ResponseFilterLifecycleIntegrationTest.@BeforeAll` reloads the JVM-wide CsrfGuard singleton and
     never restores it; Surefire reuses forks (`forkCount=4`, `reuseForks=true`).
   - The negative control asserts Tomcat's broken empty body under the default descriptor setting;
     a Tomcat patch could turn it red for a non-regression. `FINISHED_AFTER_FORWARD` already pins
     the mechanism and `descriptorSetting()` already pins the shipped contract.
   - New test file uses the SPDX short header; 125 test files already do, so
     `docs/copyright-header-carlos.md` and practice have drifted. Follow-up, not in-PR.

## Non-goals for the plan

Consolidating capture ownership into one wrapper; changing `suspendWrappedResponseAfterForward`;
the shared `DeferredContentLength` refactor; copyright-header policy.
