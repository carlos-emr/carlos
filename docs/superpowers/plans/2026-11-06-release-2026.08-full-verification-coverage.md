# Release 2026.08 Full Verification Coverage Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce executable, source-bound evidence that every change on `release/2026.08` that is not on `main` is correct, complete, free of unintended breaking changes and free of silent failures, across four layers: Java unit, Java integration (H2 and native MariaDB), Node, and Playwright against the packaged install.

**Architecture:** The release branch already carries the system of record for this work (PR #5655): the 40-workstream matrix `docs/testing/release-2026.08-verification.json`, the fail-closed evidence verifier `scripts/ci/verify-release-evidence.py`, the scope audit `scripts/ci/release-scope-audit.py`, strict browser mode (`scripts/run-playwright-suite.js --strict-release`) and the outcome ledger `docs/testing/release-2026.08-known-outcomes.json`. This plan does not build a parallel framework. It (1) runs every executable lane and collects baseline evidence, (2) closes the gaps the inventory exposes, (3) adds the tests and browser checks that are missing, (4) converts the eleven `external` checks into executable adapters or reviewed dispositions, and (5) ends when `verify-release-evidence.py verify` exits 0 with zero BLOCKED, SKIP, known-fail or unexpected-pass outcomes.

**Tech Stack:** Java 25, Maven, JUnit 5, AssertJ, H2, MariaDB 11.8.8 (`innodb-page-size=32768`, `sql-mode=`), JaCoCo 0.8.16; Node 22, npm 10.9.9, `node --test`; Playwright with the lockfile Chromium through `scripts/lib/playwright-harness.js`; Python 3 with the hash-pinned `scripts/ci/requirements.txt`; Ubuntu 26.04 systemd container for packaged installs (`scripts/deb-docker-validation.sh`); nginx + ModSecurity front door on `:443`.

**Spec:** Section 1 of this document (the measured scope inventory) plus `docs/testing/release-2026.08-verification.md`, `docs/release-notes-2026.08.md`, `docs/ui-tests/test-only-release-issues.md`, `docs/ui-tests/harness-coverage-5456.md`, `docs/ui-tests/app-findings-log.md` and `CLAUDE.md`. **Rules that bind every task.**

1. Topic branches start from `origin/release/2026.08` and PRs target `release/2026.08` (never `main` or `develop`). Commits are Conventional Commits with DCO sign-off (`git commit -s`). Use `test(...)` for test-only work.
2. This is test-only work. A check that exposes a product defect fails, and the defect is recorded in `app-findings-log.md` with a reproduction, then filed as a GitHub issue. Never encode a defect into a check as the expected result, never skip or quarantine a test to go green, never add a synthetic "fault endpoint" to the shipped WAR.
3. `.claude/settings.json` denies writes to `.github/**` and `database/**`. Workflow changes are written as a proposal for a maintainer in `docs/ui-tests/playwright-ci-proposal.md` (Task 28); migrations are never touched.
4. Every new Java test follows `should<Action>_<context><Condition>` (exactly one underscore), carries `@Tag("unit")` or `@Tag("integration")` plus a layer tag, extends `CarlosUnitTestBase` or `CarlosTestBase` (or is an isolated-JPA integration test with `IsolatedJpaTestDatabase`), and tests only methods that exist. Every new Node test is `scripts/<name>.test.js` run by `node --test`. Every new browser check is `scripts/<name>-playwright-checks.js` on the shared harness, owns FAKE-marked fixtures, cleans up by key, has a manifest entry and an npm alias, and is validated live on the packaged install before its PR opens.
5. SKIP is unavailable coverage, never a pass. `--strict-release` turns SKIP, known-fail, unexpected-pass, cleanup failure, missing structured result and changed deployment identity into failures. Use it for every release run.
6. Disposable targets only: `CARLOS_DISPOSABLE_HOST=true`, `ALLOW_NON_LOCAL_BASE_URL` only for a throwaway deployment, synthetic data only, no PHI anywhere in evidence, receipts or logs.
7. Evidence is immutable: commit before collecting receipts; a source or plan change invalidates the run; a failed attempt is never erased by a later retry.
