# Release 2026.08 Full Verification Coverage Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce executable, source-bound evidence for every in-scope changed contract across Java unit, H2/native MariaDB integration, Node and packaged Playwright, with explicit coverage of compatibility, data integrity and silent failures. A passing run supports the named assertions; it is not proof that all possible defects are absent. Unexecuted requirements and unresolved defects remain release blockers.

**Architecture:** The release branch already carries the system of record for this work (PR #5655): the 40-workstream matrix `docs/testing/release-2026.08-verification.json`, the fail-closed evidence verifier `scripts/ci/verify-release-evidence.py`, the scope audit `scripts/ci/release-scope-audit.py`, strict browser mode (`scripts/run-playwright-suite.js --strict-release`) and the outcome ledger `docs/testing/release-2026.08-known-outcomes.json`. **Rules that bind every task.**

1. Topic branches start from `origin/release/2026.08` and PRs target `release/2026.08` (never `main` or `develop`). Commits are Conventional Commits with DCO sign-off (`git commit -s`). Use `test(...)` for test-only work.
2. This is test-only work. A check that exposes a product defect fails, and the defect is recorded in `app-findings-log.md` with a reproduction, then filed as a GitHub issue. Never encode a defect into a check as the expected result, never skip or quarantine a test to go green, never add a synthetic "fault endpoint" to the shipped WAR.
3. `.claude/settings.json` denies writes to `.github/**` and `database/**`. Workflow changes are written as a proposal for a maintainer in `docs/ui-tests/playwright-ci-proposal.md` (Task 28); migrations are never touched.
4. 6. Disposable targets only: `CARLOS_DISPOSABLE_HOST=true`, `ALLOW_NON_LOCAL_BASE_URL` only for a throwaway deployment, synthetic data only, no PHI anywhere in evidence, receipts or logs.
7. Evidence is immutable. Freeze a clean source commit, plan hash, toolchain and candidate before qualification. Keep live notes outside the checkout. Separate exploratory/historical roots from final qualification and retain a linked attempt history. Source/plan changes require a new build and complete qualification series.
