# Administration and email workflows (#3774)

The security workflow creates a uniquely named unusable login, searches by username, verifies masking, renames it, asserts the password/PIN remain byte-identical, and reopens it to verify provider ownership. It exercises the real administration iframe navigation and only deletes its own security row. The installed-DEB run found the editor's broken relative stylesheet path (#3785); the context-relative correction is included here. Positive validation of that correction requires the rebuilt DEB.

The email workflow owns a patient, eForm, LOCAL sender, consent and delivery log. It clicks the eForm Email control, validates recipient and sender selection, checks that a missing subject preserves the draft without delivery, sends through a loopback-only SMTP sink, and checks exactly one captured message and successful database log with no unwanted clinical note. It then searches Administration email status by sender/status/date. The sink never relays, accepts only the exact synthetic recipient, bounds payload size and erases captured content on close. The process must run on the application host; it uses the reserved example.com domain because the application's email validator rejects the reserved but non-public invalid TLD. No external mail is sent.

The email test requires existing active consent configuration and uses the extended tier. It does not claim encrypted-attachment, SMTP TLS, external-provider or retry coverage. All four email steps, including the administration status filter, passed in the Ubuntu 26.04 VM with the installed validation12 DEB. The sink's own tests cover rejection, incomplete DATA and cleanup. Failed fixture cleanup is a failure, with parent records retained for recovery; the initial wrong-column fixture was recovered explicitly before rerun.

`admin-login-text-playwright-checks.js` adds the sixth administration route: an empty agreement upload must fail visibly without changing text or validity, and a valid synthetic upload must persist exact bytes and reopen with the selected validity. This extended check requires `PLAYWRIGHT_ALLOW_LOGIN_TEXT_WRITE=true` and `DOCUMENT_DIR` on an isolated application host. It snapshots and restores the original file bytes/owner/mode and validity rows, refusing to erase unexpected concurrent changes. Live validation is pending the next VM run.
