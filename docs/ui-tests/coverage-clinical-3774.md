This group executes the release's BCAR 2007/2012 form population and patient-scoped load/save delegation; workflow creation, state/date updates and all three list projections; RH state descriptions, patient filtering and decision-support result propagation; inbox dispatch/authorization and populated summary versus empty paginated results; and drug-interaction DTO effect translation, malformed severity, identifier normalization and description fallback.

Local validation after merging the current release branch: 59 focused clinical JUnit cases and 43 mutation-method contract cases passed (102 total). The full Java source compile, Playwright manifest/harness regressions, and selection of both the RH and BC billing checks also passed. A prior disposable mutation forcing every workflow transition to state 1 was detected. DAO/controller boundaries in the unit cases are mocked; the separate live RH workflow checks the installed application and MariaDB. Neither tier claims clinical-guideline validation. BCAR SQL assertions verify that both patient and record scope reach the helper, while the actual form transformations execute. Fixtures contain only synthetic values.

RH prevention action tests additionally verify denied writes stop before factory construction, existing workflow updates retain patient/session-provider binding, and a newly created workflow ID reaches the saved form. Follow-up negative controls exposed #3798: unrelated workflow IDs were accepted, save errors continued toward a zero-record result, and the real URL helper returned an unconfigured Struts result name hidden by the initial test stub. Both RH mutation actions now require POST and patient/workflow ownership, and execute their database changes in one Spring transaction. Failed saves return an explicit error; successful saves return the configured view and reload the saved record ID. The initial installed-DEB browser run also exposed a broken formScripts.js path and a call using a nonexistent provider selector; both are corrected.

The add-workflow action is also covered when both blood measurements are submitted: the patient and session provider reach both writes before commit. A failure on the second measurement requests rollback after either creating or updating the workflow, returns HTTP 500, and never commits. An unrelated workflow is rejected before constructing the measurement writer. These unit tests verify transaction decisions with mocked persistence; they do not claim a live measurement rollback rehearsal.

`rh-form-workflow-playwright-checks.js` opens the Forms hover menu through the patient chart, saves a new RH form/pregnancy, reopens it and updates its state/comments, rejects GET and unrelated workflow IDs, and probes rollback when MariaDB rejects an overlong field. It uses an owned patient; if the deployment has no RH registration, it creates and removes an owned temporary form-menu entry. Existing hidden registrations remain unchanged and cause an explicit SKIP. The rollback probe requires strict SQL mode.
