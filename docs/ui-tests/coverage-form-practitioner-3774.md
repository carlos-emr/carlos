# Legacy form practitioner number coverage (#3774)

The release replaces hand-built practitioner numbers in four legacy form records with `PractitionerNumber.ohipRequisition`. `LegacyFormPractitionerUnitTest` exercises each record through its provider lookup, rather than testing the formatter alone. The three mental-health forms each cover a missing OHIP billing number, a valid number, and fallback to the patient's provider when the selected provider has no number. The lab requisition covers the same paths, including its specialty code. A missing number must leave the field empty; the former `0000--00` value was rejected by the packaged front door when a form was saved.

The RH browser workflow now reopens the owned record from the patient's saved forms list. The chart's transient navigation does not expose a saved-form anchor after the save, while `ViewFormlist` does. For the rollback check, it creates temporary insert and update triggers that reject a form write, verifies the workflow update also rolls back, and drops both triggers in `finally` and in fixture cleanup. This works with the package's intentionally empty MariaDB SQL mode; overlong text alone is silently truncated there.

Validation: `mvn -o -B -Dtest=LegacyFormPractitionerUnitTest -Dcheckstyle.skip -Dspotbugs.skip -Dpmd.skip test` ran 12 cases, with zero failures or errors. The installed `rh-form-workflow-playwright-checks.js` passed all four workflow steps on the aggregate release package and disposable database. The new Java cases are isolated tests with mocked JDBC results.
