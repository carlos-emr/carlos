# Synthetic development patients from Synthea (#6148)

`generate_dev_patients.py` turns patients that the CARLOS project generates with
[Synthea](https://github.com/synthetichealth/synthea) into an additive SQL file for the **development**
database: 22 adults with long, consistent histories (several conditions, medicine changes over years,
lab values, vaccines and visits), for testing the AI chart tools and anything else that needs a full
chart.

- Open medicine courses end three years after the file is loaded (`DATE_ADD(CURDATE(), INTERVAL 3 YEAR)`), so
  they stay current; the file's text stays the same on every run.
- Output: `.devcontainer/db/scripts/demo-synthetic-patients.sql`, loaded by
  `.devcontainer/db/scripts/populate_db.sh` after `development.sql` and the name sanitization.
- **Never applied to a production database.** The packaged demo-data load (`carlos-ctl demo-data`)
  does not use it yet.
- Synthea is not run during the build: it is run once with fixed settings (`run_synthea.sh`), the
  generator converts its CSV output, and the generated SQL file is committed.

Synthea's CSV output stays **out of the repository**. To rebuild, download the jar to a folder of its
own, and the Canadian files of synthea-international (commit `83d1ab7d9a73f5a5fcd7fa0a2d3f3b4eaf725d34`,
folder `ca/src/main/resources`) to another, then run, from the repository root (Java 17 or newer, about
2 GB of memory, a few minutes):

```bash
scripts/devdata/synthea/run_synthea.sh /path/to/synthea-with-dependencies.jar /path/to/ca/src/main/resources \
    /path/to/empty-folder
python3 -I scripts/devdata/synthea/generate_dev_patients.py \
    --csv /path/to/empty-folder/csv \
    --out .devcontainer/db/scripts/demo-synthetic-patients.sql
```

`run_synthea.sh` refuses a jar with another SHA-256 and fixes every setting that would otherwise come
from the clock or the machine: two runs on 12 November 2026 wrote byte-identical CSV files (181 patients,
about 101 MB) in about three minutes each. The script also fixes the JVM's locale
(`en_US`), time zone (`America/Toronto`) and file encoding (UTF-8), the values the pinned run used, so the
shell's own locale and time zone don't matter. Only the Java build is not fixed: the pinned output was made
with OpenJDK 21.0.11+10 (the development container's Java). A rerun with another Java may write different
files; the generator then refuses them rather than using them. The generator refuses CSV files with another digest
(`--allow-other-input` overrides, for trying another seed or release), and the same CSV files always
give the same SQL file, byte for byte.

Names, places, postal codes, phones and health numbers come from the generator, not from Synthea (see
"FAKE identities"), so Synthea's own names and places never reach the file. The Canadian files make the
population Ontario-shaped (age, sex and income mix); `run_synthea.sh` checks each by SHA-256 and uses only
its data files, because that folder's own `synthea.properties` (2022) predates v4.0.0's settings.

## What a patient looks like in CARLOS

| Synthea table | CARLOS | Notes |
|---|---|---|
| patients | `demographic` + `admission` (program 10034, as every demo patient) | See "FAKE identities" |
| conditions | CPP **Ongoing Concerns** (one note each), **Medical History** (past events with their years), `dxresearch` (ICD-9) | `codemaps.CONDITIONS`; dental, acute and minor-injury conditions are left out |
| medications | `drugs` (custom drugs: generic name, strength, instructions, ATC, `long_term`) | `codemaps.MEDICINES`; hospital-only products left out; renewals merged into courses; courses that ended more than 3 years ago left out |
| allergies | `allergies` (`nonDrug` for food and environment; "No Known Drug Allergies" when none) | |
| immunizations | `preventions` + `preventionsExt` (name, dose, route, site, comment) | `codemaps.IMMUNIZATIONS`, CARLOS prevention names; last 10 years |
| observations | `measurements` in Canadian units (BP as "sys/dia", A1C, LDL, SCR, EGFR, ACR, WT, HT, BMI and more) | `codemaps.MEASUREMENTS`; last 6 values per type within 6 years |
| encounters | short visit notes (`casemgmt_note`): reason, new diagnoses, vitals, results, medicines started or stopped, vaccines | Only what Synthea recorded at that visit; newest 12 within 3 years |

Each patient also gets a **Reminders** note saying it is a synthetic test patient. Lab reports as
HL7 messages are a possible follow-up.

## FAKE identities

- Names: Synthea's first and last names without their digits, both prefixed `FAKE-` (as
  `demo-name-sanitization.sql` does for every demo patient, so a re-run of it changes nothing).
- Health numbers: 10-digit Ontario-style numbers that **fail the check digit**.
- Addresses, towns, postal codes (`Z9Z 9Z9` style) and phones (`905-555-01xx`) are invented.
- No Synthea identifier is carried over: every id in the file is a CARLOS integer, and note
  `uuid`s are made by MariaDB's `UUID()` at load time.
- `demographic_no` **90001–90099** belongs to this file (`development.sql` uses 1–3000). The file
  deletes that range first, so loading it again is safe. MariaDB moves the `demographic`
  AUTO_INCREMENT past 90022, so patients added in a development database after this load are numbered
  from 90023.
- Each patient's most responsible provider (MRP, `provider_no`) is one of `development.sql`'s demo doctors
  (providers 7–20); the referring family doctor field is left empty.
- An existing development database (a volume that never re-runs `populate_db.sh`) can load it by hand:
  `mariadb -h db -u root carlos < .devcontainer/db/scripts/demo-synthetic-patients.sql`.

## Clean-up rules

Synthea's raw output contradicts itself in places. Every change is made by one of these rules, and each
patient's block in the SQL file lists the rules that fired for it.

| Rule | What | Why |
|---|---|---|
| R1 | An HbA1c below 4.0%, or below 5.0% for a patient with diabetes, becomes about 7–9% for a patient with diabetes (a fixed value per patient, small visit-to-visit steps), 5.4% otherwise | Synthea gives 3.1% or 4.0% at every visit to some patients on insulin |
| R2 | Two medicines of one class (statin, ACE inhibitor/ARB, beta-blocker, P2Y12 inhibitor, ASA, contraceptive, NSAID, antihistamine, SNRI) or two strengths of one generic taken at once: the one started last is kept, the other ends the day before | Two statins, or lisinopril 10 mg and 40 mg, both "current" |
| R3 | A P2Y12 inhibitor (clopidogrel, prasugrel, ticagrelor) ends 12 months after it started | Prasugrel open for ten years after a heart attack |
| R4 | An antihistamine or short-term medicine left open since childhood is dropped | Diphenhydramine "current" since age 5 |
| R5 | Anemia moves to past history when the last hemoglobin is normal (≥ 120 g/L women, ≥ 130 g/L men) | "Anemia" beside a hemoglobin of 168 g/L |
| R6 | One creatinine per day (serum first); eGFR recomputed from it with CKD-EPI 2021; chronic kidney disease listed without its stage | Creatinine 1.8 mg/dL beside an eGFR of 114, and "stage 1" beside an eGFR of 32 |
| R7 | An antibiotic course left open ends 10 days after it started | |
| R8 | Monthly or yearly renewals of one medicine are merged into one course | Synthea renews every prescription at each visit |
| C1 | US-only products are replaced by the usual Canadian ones (Humulin 70/30 → 30/70, albuterol → salbutamol, hydrocodone/acetaminophen → acetaminophen/codeine, milnacipran → duloxetine, …) | Each entry says so in `codemaps.py` (`canadian=`) |
| S | A Synthea medicine with no code-map entry is left out, never guessed | |

## Tests

```bash
python3 -m unittest discover -s scripts/devdata/synthea/tests -t .
```

The tests write a tiny Synthea-shaped CSV folder to a temporary directory (no Synthea run): determinism,
health numbers that fail the check digit, no UUID or long hex string in the output, the id range, the
clean-up rules, the SQL quoting, the input digest covering each CSV file, and a clean refusal of a
folder with a CSV missing.
